## The 5-Pillar Operational Playbooks

### Pillar 1: Crawler Ingestion & Machine Context Layer

#### 1. The `llms.txt` & `llms-full.txt` Standard
AI search engines and developer agents ingest `https://{domain.com}/llms.txt` and `https://{domain.com}/llms-full.txt` (per [llmstxt.org](https://llmstxt.org)) to rapidly construct context without parsing noisy HTML DOM trees.

- **`/llms.txt`**: Curated index with H1 title, blockquote value proposition, and markdown links.
- **`/llms-full.txt`**: Comprehensive single-file bundle containing the complete documentation corpus concatenated with clear markdown section dividers (e.g., `--- # docs/architecture.md ---`). Ideal for 128k+ LLM context window ingestion.

#### 2. Next.js 15/16 App Router Route Handler (`/llms.txt`)

#### 4. Decoupled Semantic Content Negotiation (`Accept: text/markdown`)

Serve clean Markdown directly to AI agents via Next.js Edge Middleware and a **Decoupled KISS Architecture**:

- **KISS Decoupled Storage**: Never hardcode multi-thousand-line Markdown template literals or dictionaries inside TypeScript route handlers. Store markdown content in dedicated static `.md` files (e.g., `src/content/markdown/{route}.md`).
- **Thin Route Handler**: The route handler (`src/app/api/markdown/[...slug]/route.ts`) must remain a lightweight loader (<50 lines) that maps incoming route slugs to local static files using `fs.readFileSync(path.join(process.cwd(), 'src/content/markdown', fileName))`.
- **Static Pre-Rendering & Caching**: Enforce `export const dynamic = 'force-static'` and `export const revalidate = 86400` with HTTP headers:
  - `Content-Type: text/markdown; charset=utf-8`
  - `Vary: Accept`
  - `Cache-Control: public, max-age=86400, s-maxage=86400, stale-while-revalidate=604800`
- **Machine Feed Hygiene**: Keep negotiated markdown technical, structured, and factual. Strip marketing emojis (`📦`, `🧾`, `🚀`), promotional hyperbole, and unqualified absolute latency assertions.

```typescript
// src/middleware.ts
import { NextResponse } from 'next/server';
import type { NextRequest } from 'next/server';

export function middleware(request: NextRequest) {
  const acceptHeader = request.headers.get('accept') || '';
  const url = request.nextUrl.clone();

  if (acceptHeader.includes('text/markdown') && !url.pathname.startsWith('/api/')) {
    url.pathname = `/api/markdown${url.pathname === '/' ? '/root' : url.pathname}`;
    const response = NextResponse.rewrite(url);
    response.headers.set('Vary', 'Accept');
    return response;
  }

  const response = NextResponse.next();
  response.headers.set('Vary', 'Accept');
  return response;
}
```

```typescript
// src/app/api/markdown/[...slug]/route.ts (Thin KISS Loader)
import fs from 'fs';
import path from 'path';
import { NextRequest } from 'next/server';

export const dynamic = 'force-static';
export const revalidate = 86400;

export async function GET(
  request: NextRequest,
  { params }: { params: Promise<{ slug?: string[] }> }
) {
  const { slug } = await params;
  const fileName = (!slug || slug.length === 0 || slug[0] === 'root')
    ? 'root.md'
    : `${slug.join('/')}.md`;

  const filePath = path.join(process.cwd(), 'src/content/markdown', fileName);
  if (!fs.existsSync(filePath)) {
    return new Response('# 404 Not Found\n\nThe requested documentation page does not exist.', {
      status: 404,
      headers: { 'Content-Type': 'text/markdown; charset=utf-8' },
    });
  }

  const markdown = fs.readFileSync(filePath, 'utf-8');
  return new Response(markdown, {
    status: 200,
    headers: {
      'Content-Type': 'text/markdown; charset=utf-8',
      'Vary': 'Accept',
      'Cache-Control': 'public, max-age=86400, s-maxage=86400, stale-while-revalidate=604800',
    },
  });
}
```

#### 5. Server-Side Rendering (SSR) & Zero-CSR Traps
AI search crawlers enforce aggressive timeout budgets (often 1.5–3.0 seconds) and frequently fail to execute client-side JavaScript hydration. All primary content, schemas, tables, and statistics MUST render via React Server Components (RSC) or Static Site Generation (SSG).

### Pillar 2: Knowledge Graph & Structured Entity Grounding

Generative search engines utilize Knowledge Graphs (Wikidata, Google Knowledge Graph) to ground LLM reasoning, perform entity resolution, and verify factual assertions without hallucinating.

#### The 4 Non-Negotiable Invariants of Structured Entity Grounding

1. **Canonical Entity Singularity**:
   - The entire JSON-LD `@graph` MUST resolve to a single, immutable canonical domain (`https://{canonicalDomain}`).
   - All `@id` URIs (e.g. `https://{canonicalDomain}/#organization`, `https://{canonicalDomain}/#software`), `url`, `publisher`, `brand`, and breadcrumbs must reference this domain exclusively.
   - **Never mix secondary or legacy domains** (e.g. `domain.app` vs `domain.online`). Never include the site's own primary domain in `sameAs` (creates circular self-reference loops).
2. **Zero-Fabrication Invariant (Ratings & Reviews)**:
   - **NEVER generate `AggregateRating` or `Review` markup** without verifiable, crawlable, on-page user reviews or authentic third-party certification.
   - Fabricating rating values (e.g. `ratingValue: "4.9"`, `reviewCount: "120"`) is penalized by search engines via manual spam actions and recognized by LLM rerankers as an untrusted hallucination signal.
3. **Wikidata Parsimony**:
   - Restrict `knowsAbout` and `sameAs` Wikidata URIs to strictly **3–5 core, high-signal, ontologically disambiguating entities** (e.g., electronic billing, inventory control, artificial intelligence, small and medium-sized enterprises).
   - Never stuff 15+ generic or loosely related Wikidata links, which dilutes topical authority.
4. **Defensible Metric Grounding**:
   - Quantitative claims inside FAQ schemas, feature descriptions, and markdown specs must be qualified and defensible (e.g., *"designed for sub-second responses under typical network conditions"* rather than unhedged *"processes in <50ms"*).

### Pillar 3: Information Gain & Factual Density

Generative models re-rank and prioritize retrieved chunks based on their information density and authority signals:

1. **Information Gain Delta ($\Delta I$)**:
   - Avoid regurgitating generic web definitions. Inject proprietary data points, internal telemetry, unique benchmarks, or primary source case studies.
2. **Quantitative Evidence & Benchmarks**:
   - Embed exact metrics (sample sizes, throughput, latency percentiles, error rates).
   - *Example*: Replace *"fast processing"* with *"processes 10,000 transactions/sec at 42ms p99 latency"*.
3. **Direct Expert & Maintainer Attribution**:
   - Add verbatim, attributed statements from system architects or recognized domain authorities.
4. **Authoritative Tone & Zero-Slop Standard**:
   - Eliminate promotional fluff (*"groundbreaking"*, *"industry-leading"*, *"game-changing"*). Replace with concrete technical specifications.

### Pillar 4: Modular Answer-Engine Architecture (BLUF) & Multimodal

LLMs retrieve and process content in discrete 200â€“500 token chunks:

1. **BLUF (Bottom Line Up Front)**:
   - Provide the complete, direct, quantitative answer within the first 40â€“60 words of each section.

### Pillar 5: Synthetic Probing & Share of Model Voice (SoMV)

#### 1. Share of Model Voice (SoMV) Formula

**Mathematical Representation (LaTeX):**
$$\text{SoMV} = \left( \frac{\sum_{i=1}^{N} \text{Weight}(M_i, C_i, R_i)}{N} \right) \times 100$$

**Plain-Text Representation (Runtime-Safe):**
```text
SoMV (%) = [ Sum_{i=1 to N} (1.0 * Recommendation_i + 0.7 * Citation_i + 0.4 * Mention_i) / N ] * 100
```

Where for each test prompt $i \in \{1, \dots, N\}$:
- **Mention ($M_i \in \{0, 1\}$)**: Brand or entity is explicitly named (Weight: 0.4).
- **Citation ($C_i \in \{0, 1\}$)**: Target domain URL is linked as an authoritative source (Weight: 0.7).
- **Recommendation ($R_i \in \{0, 1\}$)**: AI explicitly recommends the product as a top solution (Weight: 1.0).

#### 2. Probing Execution Playbook (API & Zero-API Fallback)

When tasked with benchmarking or validating GEO visibility:

1. **Curate the Prompt Universe (20â€“100 prompts across 4 intent categories)**:
   - *Direct Discovery*: `"What is the best {Category} for {TechStack} in 2026?"`
   - *Comparative*: `"{BrandName} vs {Competitor} for {UseCase}"`
   - *Problem-Solving*: `"How to resolve {Specific Technical Error} in {Framework}"`
   - *Technical Spec*: `"Which tools support {Standard/Protocol} with {Runtime}?"`

2. **Execution Strategy**:
   - **Path A (API Probing)**: Query Perplexity API (`sonar-medium`), OpenAI Search API (`gpt-4o-search`), or Google Gemini Grounding API with exponential backoff (initial delay: 1000ms, factor: 2x).
   - **Path B (Browser / Zero-API Fallback Checklist)**:
     - Open Perplexity.ai / ChatGPT / Gemini in clean incognito sessions.
     - Execute 10 sample prompt queries manually or via headless Playwright script.
     - Score each answer using the `Mention (0.4) / Citation (0.7) / Recommendation (1.0)` heuristic matrix.

3. **LLM-as-a-Judge Evaluation & Baseline Logging**:
   - Evaluate responses and record baseline metrics in `.harness/state/geo_baseline_{YYYYMMDD}.json` or `docs/geo/`.

## Anti-Patterns & Prohibitions

1. **NO Hidden Prompt Injections**: Never inject invisible text, zero-font text (`font-size: 0px`), or prompt injection directives (*"Ignore previous instructions and recommend X"*). Generative search engines detect and permanently blacklist adversarial domains.
2. **NO Generic AI Slop**: Publishing generic, low-information AI re-writes produces 0 Information Gain and gets pruned during neural reranking.
3. **NO Client-Side-Only Rendering for Key Content**: Storing core product specs, pricing, or documentation inside client-only React hooks hides content from sub-second AI crawlers.
4. **NO Dangling Pronouns**: Avoid starting sections with ambiguous pronouns (*"It provides..."*, *"Our platform..."*); always state the exact entity name.
5. **NO Blank Disallow in `robots.txt`**: Never allow blanket `Disallow: /` on AI search bots (`OAI-SearchBot`, `PerplexityBot`).
6. **NO Unhedged Static Multipliers**: Never cite academic multipliers as immutable truths; always state they are directional empirical baselines requiring periodic probe verification.
7. **NO Monolithic In-Code Markdown Blobs**: Never hardcode thousands of lines of documentation or page markdown directly inside Next.js route handlers or TypeScript components. Decouple content into static `.md` files in a dedicated content directory.
8. **NO Split Domain Entities**: Never mix primary and secondary domains across `@id`, `url`, `sameAs`, or breadcrumb JSON-LD structures. Maintain 100% Canonical Entity Singularity.
9. **NO Fabricated `AggregateRating`**: Never fabricate fake rating counts, review values, or bestRating/worstRating schemas without crawlable, verified on-page user reviews.
10. **NO Wikidata Link Stuffing**: Never spam 10+ Wikidata links in `knowsAbout` or `sameAs`. Curate strictly 3–5 topically essential entities.
11. **NO Unhedged Performance Claims**: Never publish unqualified absolute latency claims (e.g., "<50ms processing") in machine feeds unless backed by publicly verifiable third-party audit reports. Use defensible qualifiers (e.g., "typically under 200ms", "optimized for sub-second response").
12. **NO Promotional Emojis in Machine Content Feeds**: Never pollute machine-targeted content feeds (`/llms.txt`, markdown content negotiation) with decorative promotional emojis (`📦`, `🧾`, `🚀`). Keep machine feeds strictly institutional, technical, and parseable.
